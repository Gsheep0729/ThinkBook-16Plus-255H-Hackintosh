# 安装实录：从首次启动到 macOS 15.8.2

本页重写本机安装记录的公开版本。过程照片保留当时画面，按阶段解释；文件名受多系统时钟偏移影响，不用它推断所有事件的绝对先后。它不是自动安装器，也不授权抹除读者的分区。

## 安装前提与CPU组合

机器是ThinkBook 16+ / 21TL、Ultra 7 255H，使用独显模式。历史安装时用户已关闭VT-d；该事实不是本次要求修改BIOS的指令，其他机器按自身前提判断。Above 4G实际值没有证据，不能归因为它导致启动慢或显卡限速。

原生成EFI可进入内核，但照片停在trust caches附近，没有完整panic，最后一行不能确定根因。备份后只组合调整：

```text
Kernel/Add/CpuTopologyRebuild.kext/Enabled = false
Kernel/Quirks/ProvideCurrentCpuInfo = true
```

其他141个EFI文件及原日志保持；当时1.0.9静态校验通过。调整后进入Recovery并完成安装，支持“两项组合后的安装结果”，不能断言单项唯一根因。`ctrsmt=full`仍在历史参数中，不能说已停用kext仍靠它调度。

## Recovery、目标分区与重启

进入Recovery后，在本机原已准备的专用约214.75 GB分区上建立APFS，再安装至MacOs。历史盘号不是读者操作目标；不抹父磁盘、不动共享数据分区，不因Windows把APFS显示为空闲就格式化它。

首次重启阶段按安装进度进入macOS Installer，安装完成后进入本地MacOs；Recovery本身仍可见，不代表前面的安装白费。经过后续设置进入15.8.2桌面，键盘助手按屏幕提示识别“左Shift右边”的实物键。

## 内置ESP与独立引导

KIOXIA已有约1.05 GiB FAT32 ESP，不是空盘。原Windows/Linux目录、两块ESP和固件入口分别保留；复制OC前先核对物理盘、分区和现有目录冲突，不能凭卷名或修改时间判断。历史记录确认OpenCore (KIOXIA)在BIOS可见，不据此给拔U盘冷启动、多系统全部回归提前打勾。

## 显卡后的基线变化

安装阶段“图形31 MB”只代表当时尚未完成显卡驱动。NVIDIA 2.6.6系统侧安装后，RTX5060/Metal3/8GB/3200×2000@165Hz及默认200% HiDPI有通过记录，背光和扬声器另有用户确认。系统kext、GPUBundles、AuxKC与EFI一起构成恢复边界，不能只恢复显卡前EFI就声称完整卸载。

[驱动运行画面](../照片/IMG20261104042438.jpg)显示当时2.6.6组件运行；硬件全面验收以[状态表](../验收状态表.md)为准，第三方工具的识别文字不能取代逐项功能测试。

## 后续机型与收尾

最初MacBookPro16,2只是安装历史。11月5日改为MacPro7,1并更换独立身份，20:20:42新启动匹配通过；不公开身份值，不以此宣称蓝牙、性能、睡眠或Apple服务修复。最后私有配置基线`79665d05…`不能由安装阶段旧整包覆盖。
